6.1 Struktur Direktori Proyek (Monorepo Workspace)

Saya menata seluruh berkas proyek dalam struktur direktori yang bersih dan terisolasi antara logika server dan logika klien di dalam workspace website_intersis: 

website_intersis/
|-- backend/                  # Server-side REST API (Node.js & Express)
|   |-- src/
|   |   |-- config/           # Konfigurasi pool koneksi database MySQL (db.js)
|   |   |-- controllers/      # Logika pemrosesan bisnis (Admin & Public controllers)
|   |   |-- middlewares/      # Interceptor HTTP (Auth, ErrorHandler, RateLimiter, Upload)
|   |   |-- routes/           # Pemetaan rute URL ke controller (Admin & Public routes)
|   |   |-- scripts/          # Skrip bantu pemeliharaan dan seeding bilingual
|   |   |-- seeders/          # Skrip inisialisasi data dummy dan data master awal
|   |   |-- utils/            # Fungsi utilitas (Response formatter, Slugify, FileCleanup)
|   |   |-- validators/       # Aturan validasi payload input (express-validator)
|   |   +-- server.js         # Entry point server Express utama
|   |-- uploads/              # Penyimpanan lokal aset media berkas terunggah
|   |-- .env                  # Variabel lingkungan server (Port, DB credentials, JWT Secret)
|   +-- package.json          # Dependensi pustaka backend
|
|-- frontend/                 # Client-side SPA (React.js & Vite)
|   |-- src/
|   |   |-- assets/           # Berkas statis gambar, logo dummy, dan diagram
|   |   |-- components/       # Komponen antarmuka atomik (Layout, Navbar, Footer, Automation)
|   |   |-- context/          # State global (LanguageContext, AdminAuthContext, BrandingContext)
|   |   |-- data/             # Data statis awal dan fallback data katalog produk
|   |   |-- hooks/            # Custom React Hooks pembantu interaksi data
|   |   |-- locales/          # Kamus terjemahan teks antarmuka (Indonesian & English)
|   |   |-- pages/            # Komponen halaman (Public Pages & Admin Portal Pages)
|   |   |-- utils/            # Helper format mata uang, tanggal, dan sanitasi teks
|   |   |-- App.jsx           # Registrasi routing browser dan Suspense fallback
|   |   |-- index.css         # Design system, variabel token, dan utilitas global
|   |   +-- main.jsx          # Titik masuk rendering React ke DOM
|   |-- public/               # Aset publik langsung (favicon, robots.txt)
|   |-- index.html            # Berkas HTML utama aplikasi SPA
|   |-- vite.config.js        # Konfigurasi bundling Vite dan reverse proxy dev server
|   +-- package.json          # Dependensi pustaka frontend
|
+-- database/                 # Berkas skrip DDL SQL, relasi ERD, dan dokumentasi skema

6.2 Pola Perancangan (Design Patterns) yang Diterapkan

  • Separation of Concerns (SoC): Setiap direktori memiliki tanggung jawab tunggal. Lapisan rute (Routes) tidak memuat query database; lapisan kontrol (Controller) tidak mendefinisikan aturan parsing regex (ditangani Validator); dan lapisan tampilan (React Pages) murni menangani antarmuka pengguna.
  • Layered Controller-Service Architecture: Controller menerima permintaan, memvalidasi parameter, mengeksekusi operasi basis data melalui abstraksi koneksi terpusat, dan mengembalikan respons terstandarisasi.
  • Singleton Configuration Pattern: Objek koneksi basis data pada config/db.js dibuat sekali dan digunakan kembali di seluruh aplikasi melalui mekanisme pooling, mencegah lonjakan konsumsi memori server.
  • Fail-Safe Fallback: Pada komponen frontend publik, jika server backend mengalami latensi atau gangguan koneksi, antarmuka tetap menyajikan data cadangan terverifikasi dari modul data/ sehingga pengguna tidak pernah melihat layar putih kosong.
