3.3 Siklus Hidup Permintaan HTTP (HTTP Request & Middleware Lifecycle)

Setiap transaksi data antara antarmuka React dan server Express melalui tahapan pemrosesan sistematis sebagai berikut:

  1. Client Dispatch: Antarmuka frontend mengirimkan permintaan asinkron (menggunakan Axios atau Fetch API) dengan payload JSON atau Form-Data multipart.
  2. Security & Rate Limiter: Permintaan masuk disambut oleh middleware keamanan helmet(), kebijakan CORS, dan rate limiter IP. Permintaan yang melampaui ambang batas langsung ditolak dengan kode status HTTP 429.
  3. Authentication Guard: Pada rute terproteksi, verifyToken mengekstrak token Bearer dari header. Jika token valid, objek user didekodekan dan disimpan di req.user. Jika tidak valid atau kedaluwarsa, server mengembalikan status HTTP 401.
  4. Authorization Filter: Middleware restrictTo(roles) mencocokkan role user pada req.user.role. Akses ditolak dengan status HTTP 403 jika role tidak memenuhi wewenang.
  5. Payload Validation: Skema validasi express-validator memeriksa tipe data, panjang string, dan pola regex. Jika ada anomali, middleware validate memutus eksekusi dan mengembalikan daftar rincian error dengan status HTTP 400.
  6. Controller Execution: Controller memanggil koneksi pool MySQL, menjalankan query SQL berparameter (Prepared Statements), memproses transformasi bilingual, dan menyusun objek data.
  7. Centralized Error Handling: Apabila terjadi pengecualian (runtime exception atau kendala database), error diteruskan ke middleware errorHandler untuk dicatat ke log server dan dikembalikan kepada klien dalam format JSON yang aman tanpa membocorkan kredensial sistem.
