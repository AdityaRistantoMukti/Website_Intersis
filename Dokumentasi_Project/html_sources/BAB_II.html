2.1 Arsitektur & Standar Respons RESTful API

Saya merancang antarmuka Application Programming Interface (API) berbasis arsitektur RESTful yang memanfaatkan protokol HTTP dan format payload JSON. Seluruh endpoint mengembalikan struktur respons yang seragam untuk mempermudah integrasi dan penanganan kesalahan pada sisi klien: 

// Format Respons Sukses:
{
  "success": true,
  "message": "Data berhasil diambil",
  "data": { ... },
  "meta": { "total": 12, "page": 1, "limit": 10 } // Opsional jika paginasi
}

// Format Respons Gagal / Error:
{
  "success": false,
  "message": "Deskripsi kesalahan yang terjadi",
  "errors": [ { "field": "email", "message": "Format email tidak valid" } ] // Opsional
}

2.2 Mekanisme Keamanan, Autentikasi, & Rate Limiting

Untuk menjaga keandalan dan keamanan data perusahaan, saya menerapkan standar keamanan berlapis:

  • JSON Web Token (JWT): Endpoint administratif dilindungi dengan verifikasi token JWT melalui header HTTP Authorization: Bearer [token]. Token memiliki masa berlaku terbatas dan diverifikasi oleh middleware verifyToken.
  • Role-Based Access Control (RBAC): Sistem membatasi hak akses pengguna ke dalam tiga tingkatan melalui middleware restrictTo(...):
    • administrator: Hak akses penuh ke seluruh modul, pengaturan sistem, dan manajemen user.
    • hrd: Mengelola lowongan kerja, data pelamar, konten perusahaan, dan akun staf.
    • staff: Mengelola operasional entri konten website publik (read, create, update terbatas).
  • Rate Limiting: Saya memasang limitasi permintaan menggunakan express-rate-limit guna menangkal serangan brute-force dan Denial of Service (DoS):
    • apiLimiter: Maksimum 200 permintaan per jendela 15 menit untuk endpoint publik.
    • authLimiter: Maksimum 5 percobaan login gagal per 15 menit per alamat IP.
    • rfqSubmissionLimiter: Maksimum 10 pengiriman RFQ per 1 jam per alamat IP.
