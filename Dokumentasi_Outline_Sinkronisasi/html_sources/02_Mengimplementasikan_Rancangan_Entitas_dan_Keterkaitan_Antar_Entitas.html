Pertanyaan Desain Basis Data: Apakah diagram basis data memang dirancang dengan jumlah tabel yang ada, dan berapa total tabel yang sebenarnya dibuat?

Jawaban & Penjelasan Arsitektural: Basis data sistem (isa_career_hrd) dirancang dan diimplementasikan dengan TOTAL 15 TABEL FISIK pada lingkungan produksi. Seluruh 15 tabel ini terbagi secara sistematis ke dalam 4 Domain Fungsional:

  1. Domain 1 — Solusi Industri & B2B RFQ (2 Tabel):
    • products: Menyimpan 19 SKU produk elektronika industri (Headunit, Audio DSP, Dashcam, EMS) lengkap dengan data bilingual, spesifikasi teknis JSON, dan galeri foto.
    • rfq_inquiries: Menampung tiket formulir permintaan penawaran harga (Request for Quotation) B2B dari calon mitra internasional lengkap dengan audit IP, negara, dan skor anti-spam.
  2. Domain 2 — Profil Perusahaan, CMS & Pengaturan Konten Batam FTZ (6 Tabel):
    • company_profile: Entitas Singleton (1 baris) penyimpan visi, misi, dan profil utama korporat.
    • core_values: Menyimpan 4 nilai inti perusahaan (Inovasi, Mutu Presisi, Integritas, Keberlanjutan).
    • site_settings: Sistem CMS semi-terstruktur berbasis JSON untuk mengelola timeline sejarah pabrik, sertifikasi mutu IATF 16949/ISO, narasi keunggulan Batam Free Trade Zone (FTZ), konfigurasi hero banner, dan statistik pabrik.
    • contact_recruitment: Entitas Singleton penyimpan alamat pabrik, telepon resmi, WhatsApp sales, dan kanal media sosial.
    • gallery: Dokumentasi visual fasilitas manufaktur, lini SMT, ruang cleanroom Class 100K, dan kegiatan industri.
    • faqs: Daftar tanya jawab umum terkait kapabilitas produksi dan layanan OEM/ODM.
  3. Domain 3 — Keamanan Sistem, Manajemen Akses & Telemetri (3 Tabel):
    • users: Akun pengguna internal sistem dengan pembagian hak akses Role-Based Access Control (RBAC: Administrator, HRD Manager, Staff).
    • activity_logs: Audit trail otomatis pencatatan setiap aksi transaksi data (CREATE, UPDATE, DELETE, LOGIN) untuk transparansi operasional.
    • visitor_telemetry: Pelacakan kunjungan pengunjung portal publik (session ID, alamat IP, URL halaman, dan browser user agent) untuk analitik trafik.
  4. Domain 4 — Manajemen Fasilitas & Organisasi Internal (4 Tabel):
    • job_categories: Master kategori divisi operasional internal.
    • job_vacancies: Data lowongan kerja internal yang berelasi dengan divisi (category_id) dan pembuat lowongan (created_by).
    • programs: Program pengembangan SDM industri (Management Trainee, Magang Bersertifikat, Technical OJT).
    • benefits: Fasilitas dan tunjangan kerja internal bagi karyawan.

-- Skema DDL Fisik Tabel products (Engine MySQL 8 / InnoDB)
CREATE TABLE products (
  id int(11) NOT NULL AUTO_INCREMENT,
  model_code varchar(100) COLLATE utf8mb4_unicode_ci NOT NULL,
  category enum('headunit','audio','dashcam','automation','ems') COLLATE utf8mb4_unicode_ci NOT NULL DEFAULT 'headunit',
  badge varchar(100) COLLATE utf8mb4_unicode_ci DEFAULT NULL,
  badge_color varchar(50) COLLATE utf8mb4_unicode_ci DEFAULT NULL,
  title_id text COLLATE utf8mb4_unicode_ci NOT NULL,
  title_en text COLLATE utf8mb4_unicode_ci NOT NULL,
  short_desc_id text COLLATE utf8mb4_unicode_ci,
  short_desc_en text COLLATE utf8mb4_unicode_ci,
  specs longtext COLLATE utf8mb4_unicode_ci COMMENT 'JSON array {label, value}',
  full_specs longtext COLLATE utf8mb4_unicode_ci COMMENT 'JSON object key-value',
  diagram_type varchar(50) COLLATE utf8mb4_unicode_ci NOT NULL DEFAULT 'infotainment',
  image varchar(255) COLLATE utf8mb4_unicode_ci DEFAULT NULL,
  gallery longtext COLLATE utf8mb4_unicode_ci,
  status tinyint(1) NOT NULL DEFAULT '1' COMMENT '1=aktif, 0=nonaktif',
  sort_order int(11) NOT NULL DEFAULT '0',
  created_at timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

2.3. Eksekusi Query DQL Terindeks untuk Penarikan Data Katalog Produk

Lokasi Berkas: backend/src/controllers/public/publicProductController.js

Query DQL berikut dieksekusi secara teroptimasi menggunakan Connection Pool MySQL untuk menyajikan produk berstatus aktif (status = 1) terurut berdasarkan prioritas:

Bukti Implementasi Kode Sumber (Visual Studio Code):
backend/src/controllers/public/publicProductController.js
VS CODE • UTF-8
const pool = require('../../config/database');
const { success } = require('../../utils/response');

/**
 * GET /api/public/products
 * Mendapatkan daftar produk aktif untuk halaman publik
 */
const getProducts = async (req, res, next) => {
  try {
    const [rows] = await pool.execute(
      `SELECT id, model_code, category, badge, badge_color, image, gallery,
              title_id, title_en, short_desc_id, short_desc_en,
              specs, full_specs, diagram_type, sort_order
       FROM products
       WHERE status = 1
       ORDER BY sort_order ASC, id ASC`
    );

    // Parse LONGTEXT JSON strings &rarr; JS objects (MariaDB/MySQL compat)
    const parsed = rows.map(row => ({
      ...row,
      specs:      row.specs      ? (typeof row.specs      === 'string' ? JSON.parse(row.specs)      : row.specs)      : [],
      full_specs: row.full_specs ? (typeof row.full_specs === 'string' ? JSON.parse(row.full_specs) : row.full_specs) : {},
      gallery:    row.gallery    ? (typeof row.gallery    === 'string' ? JSON.parse(row.gallery)    : row.gallery)    : [],
    }));

    return success(res, 'Daftar produk berhasil diambil.', parsed);
  } catch (err) {
    next(err);
  }
};

module.exports = { getProducts };
