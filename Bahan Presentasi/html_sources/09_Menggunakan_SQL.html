I. Peta Outline & Struktur Pembahasan

Unit kompetensi Menggunakan SQL ini disusun secara berkesinambungan mencakup seluruh sub-judul yang didefinisikan pada diagram alur kompetensi, diaplikasikan langsung pada arsitektur website yang telah dibangun:

  • Operasi DML: Mengeksekusi manipulasi data (SELECT, INSERT, UPDATE, DELETE) menggunakan Prepared Statements berparameter aman.
  • Manipulasi tabel/view: Mengelola struktur skema tabel melalui DDL (ALTER TABLE, migrasi bilingual, produk) dan pembuatan virtual view pelaporan.
  • Stored procedure: Menyusun prosedur tersimpan di database engine untuk eksekusi batch kompleks seperti otomasi penutupan lowongan kadaluarsa.
  • Function: Memanfaatkan fungsi agregasi bawaan (COUNT, NOW, COALESCE) dan User Defined Functions untuk komputasi data terpusat.
  • Trigger: Mengimplementasikan pemicu database otomatis (AFTER INSERT/UPDATE) untuk mencatat histori perubahan ke activity_logs.
  • Commit/Rollback: Menerapkan prinsip ACID transaksi multi-tabel di Node.js (beginTransaction, commit, rollback) untuk menjaga integritas data.

exports.createJob = async (req, res, next) => {
  try {
    const { category_id, title, location, employment_type, description, requirements, form_url, status } = req.body;
    const adminId = req.user.id;

    const query = `
      INSERT INTO job_vacancies 
      (category_id, title, location, employment_type, description, requirements, form_url, status, created_by)
      VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?)
    `;
    const [result] = await db.query(query, [
      category_id, title, location, employment_type, description, requirements, form_url, status || 'draft', adminId
    ]);

    res.status(201).json({ success: true, message: 'Lowongan berhasil dipublikasikan.', id: result.insertId });
  } catch (err) {
    next(err);
  }
};

-- 1. Stored Procedure: Otomasi Penutupan Lowongan Kadaluarsa
DELIMITER //
CREATE PROCEDURE sp_archive_expired_jobs(IN p_days_threshold INT)
BEGIN
  UPDATE job_vacancies 
  SET status = 'closed', updated_at = NOW()
  WHERE status = 'published' 
    AND DATEDIFF(NOW(), created_at) > p_days_threshold;
END //
DELIMITER ;

-- 2. Trigger Otomatis: Pencatatan Audit Trail Pasca Mutasi Lowongan
DELIMITER //
CREATE TRIGGER trg_audit_job_update
AFTER UPDATE ON job_vacancies
FOR EACH ROW
BEGIN
  IF OLD.status <> NEW.status THEN
    INSERT INTO activity_logs (user_id, action, module, description, created_at)
    VALUES (NEW.created_by, 'UPDATE_STATUS', 'CAREER', 
            CONCAT('Status lowongan "', NEW.title, '" diubah dari ', OLD.status, ' ke ', NEW.status), NOW());
  END IF;
END //
DELIMITER ;

9.6. Manajemen Transaksi ACID (Begin Transaction, Commit, Rollback)

Kaitkan ke Codebase: backend/src/config/database.js & Contoh Transaksi Controller

Prinsip Atomicity diimplementasikan pada operasi yang melibatkan lebih dari satu tabel secara simultan:

backend/src/utils/transactionDemo.js 
// Implementasi Transaksi ACID: Menjamin Operasi All-or-Nothing
const db = require('../config/database');

async function executeTransactionalJobCreation(jobData, adminId) {
  // 1. Dapatkan dedicated connection dari connection pool
  const connection = await db.getConnection();
  try {
    // 2. Mulai transaksi
    await connection.beginTransaction();

    // Langkah A: Insert lowongan kerja
    const [jobResult] = await connection.query(
      'INSERT INTO job_vacancies (category_id, title, description, requirements, created_by) VALUES (?, ?, ?, ?, ?)',
      [jobData.category_id, jobData.title, jobData.description, jobData.requirements, adminId]
    );

    // Langkah B: Insert activity audit log
    await connection.query(
      'INSERT INTO activity_logs (user_id, action, module, description) VALUES (?, "CREATE", "CAREER", ?)',
      [adminId, `Menerbitkan lowongan baru ID: ${jobResult.insertId}`]
    );

    // 3. Jika kedua query sukses, komit perubahan permanen
    await connection.commit();
    return { success: true, jobId: jobResult.insertId };
  } catch (error) {
    // 4. Jika ada tahapan yang gagal, batalkan seluruh mutasi data
    await connection.rollback();
    throw error;
  } finally {
    // 5. Kembalikan koneksi ke pool
    connection.release();
  }
}

V. Matriks Tanya Jawab & Panduan Pembelaan Sidang (Q&A Defense)

Prediksi pertanyaan evaluasi dari Penguji / Asesor / Pembimbing Industri beserta jawaban teknis yang siap dipertahankan:

Q1: Mengapa Anda memilih menggunakan Prepared Statements di library mysql2 dibandingkan string concatenation biasa?
Jawaban Pembelaan Presenter: Prepared statements memisahkan antara struktur query SQL dan nilai data yang dikirimkan. Database engine mengompilasi struktur query terlebih dahulu sebelum menyisipkan data parameter, sehingga karakter khusus dari input pengguna (seperti tanda petik atau statement OR 1=1) diperlakukan murni sebagai literal string, bukan perintah SQL yang dapat dieksekusi (kebal SQL Injection).
Q2: Dalam situasi apa saja kita wajib menggunakan mekanisme Commit dan Rollback?
Jawaban Pembelaan Presenter: Transaksi commit dan rollback wajib digunakan pada setiap proses bisnis yang melibatkan lebih dari satu operasi penulisan data yang saling bergantung (multi-table write). Misalnya: saat memotong saldo pengguna sekaligus membuat riwayat tagihan, atau saat merilis lowongan kerja sekaligus mencatat log audit ke sistem HRD.
