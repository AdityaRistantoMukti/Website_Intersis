8.2. Integrasi Library Kunci di Backend & Frontend via NPM

Kaitkan ke Codebase: backend/package.json & frontend/src/i18n.js

Konfigurasi integrasi library multi-bahasa i18next pada sisi client:

frontend/src/i18n.js 
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';
import LanguageDetector from 'i18next-browser-languagedetector';
import translationID from './locales/id.json';
import translationEN from './locales/en.json';

// Inisialisasi Integrasi Eksternal Library i18next
i18n
  .use(LanguageDetector)
  .use(initReactI18next)
  .init({
    resources: {
      id: { translation: translationID },
      en: { translation: translationEN }
    },
    fallbackLng: 'id',
    interpolation: { escapeValue: false }
  });

export default i18n;

8.3. Manajemen Semantic Versioning & Penguncian package-lock.json

Kaitkan ke Codebase: package-lock.json & npm audit workflow

Penerapan aturan versioning untuk mencegah terjadinya build break pada environment produksi:

  • Caret Operator (^): Digunakan untuk dependensi yang aman menerima update Minor dan Patch (seperti "axios": "^1.20.0").
  • Exact Locking: Diterapkan pada library grafis sensitif seperti "cobe": "0.6.3" untuk mencegah perubahan shader pada update minor.
  • Integritas Hash package-lock.json: Menjamin setiap mesin pengembang dan runner Railway menginstalasi dependensi dengan checksum SHA-512 yang sama persis.
Terminal Command: Audit & Versioning Verification 
# Memeriksa dependensi yang memiliki versi baru
npm outdated

# Memindai potensi celah keamanan (vulnerabilities)
npm audit

# Menginstalasi versi terkunci persis sesuai package-lock.json di CI/CD
npm ci

V. Matriks Tanya Jawab & Panduan Pembelaan Sidang (Q&A Defense)

Prediksi pertanyaan evaluasi dari Penguji / Asesor / Pembimbing Industri beserta jawaban teknis yang siap dipertahankan:

Q1: Apa risiko jika kita tidak mengikutsertakan file package-lock.json ke dalam repositori Git?
Jawaban Pembelaan Presenter: Tanpa package-lock.json, setiap kali perintah npm install dijalankan di server produksi atau komputer tim lain, npm dapat mengunduh versi library terbaru yang berbeda dengan versi yang digunakan saat development. Jika versi baru tersebut mengandung bug atau breaking change, aplikasi produksi dapat langsung crash.
Q2: Mengapa Anda menggunakan 'npm ci' bukan 'npm install' pada skrip deployment server?
Jawaban Pembelaan Presenter: 'npm ci' (Clean Install) dirancang khusus untuk lingkungan otomatisasi dan server produksi. Perintah ini menghapus node_modules lama dan menginstalasi dependensi secara cepat dan persis 100% mengikuti checksum yang tertulis di package-lock.json, serta menolak instalasi jika package.json dan package-lock.json tidak sinkron.
