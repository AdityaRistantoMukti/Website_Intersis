2.1. Perancangan ERD dan Normalisasi Basis Data 3NF

Kaitkan ke Codebase: database/ERD.md & database/isa_career_hrd.sql

Database isa_career_hrd dirancang untuk mendukung operasional sistem multi-tier yang handal. Pemodelan mencakup 12 tabel fungsional dengan kepatuhan normalisasi ketat:

  • 1NF (Atomisitas): Kolom seperti persyaratan kualifikasi disimpan dalam format teks terstruktur atau relasi baris terpisah, bukan koma tanpa batasan.
  • 2NF (Dependensi Penuh): Setiap tabel memiliki Primary Key integer Auto Increment tunggal (seperti id), dan seluruh kolom non-kunci bergantung penuh pada ID tersebut.
  • 3NF (Bebas Transitif): Data kategori jabatan tidak disematkan sebagai string berulang di tabel lowongan, melainkan dipisah ke job_categories sehingga perubahan nama kategori tidak menimbulkan anomali pembaruan.
database/isa_career_hrd.sql 
-- Struktur Tabel Relasional Lowongan Pekerjaan (Job Vacancies)
CREATE TABLE IF NOT EXISTS job_vacancies (
  id INT AUTO_INCREMENT PRIMARY KEY,
  category_id INT NOT NULL,
  title VARCHAR(150) NOT NULL,
  location VARCHAR(100) NOT NULL DEFAULT 'Batam, Kepulauan Riau',
  employment_type ENUM('Full Time','Part Time','Internship','Contract','OJT') NOT NULL DEFAULT 'Full Time',
  description TEXT NOT NULL,
  responsibilities TEXT,
  requirements TEXT NOT NULL,
  form_url VARCHAR(500),
  status ENUM('draft','published','closed') NOT NULL DEFAULT 'draft',
  created_by INT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_jobs_category (category_id),
  INDEX idx_jobs_status (status),
  CONSTRAINT fk_jobs_category FOREIGN KEY (category_id) REFERENCES job_categories(id) ON DELETE RESTRICT,
  CONSTRAINT fk_jobs_creator FOREIGN KEY (created_by) REFERENCES users(id) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

2.2. Identifikasi Relasi Kardinalitas & Audit Trail

Kaitkan ke Codebase: database/DATABASE_DOCUMENTATION.md

Matriks relasi antar entitas mencakup hubungan kardinalitas sebagai berikut:

Relasi Antar Entitas Kardinalitas Foreign Key & Constraint Deskripsi Bisnis
job_categories → job_vacancies 1 : N category_id (ON DELETE RESTRICT) Satu divisi kategori memiliki banyak posting lowongan pekerjaan. Kategori tidak boleh dihapus jika masih ada lowongan aktif.
users → job_vacancies 1 : N created_by (ON DELETE SET NULL) Mencatat staf HRD yang merilis lowongan kerja untuk akuntabilitas internal.
users → activity_logs 1 : N user_id (ON DELETE CASCADE) Setiap login, manipulasi data produk, dan lowongan terekam lengkap beserta timestamp ke log audit.
users → company_profile 1 : 1 (Singleton) updated_by (ON DELETE SET NULL) Hanya terdapat tepat 1 baris profil korporat untuk menjaga integritas tampilan landing page.

2.3. Eksekusi Query Terindeks & Penggabungan Relasi (JOIN)

Kaitkan ke Codebase: backend/src/controllers/public/publicJobController.js

Untuk menyajikan data lowongan kepada calon pelamar, backend mengeksekusi query DQL relasional dengan prepared statements. Query ini menggabungkan tabel job_vacancies dengan job_categories menggunakan klausa LEFT JOIN:

backend/src/controllers/public/publicJobController.js 
// Eksekusi Query Relasional DQL dengan LEFT JOIN & Filter Status
exports.getPublishedJobs = async (req, res, next) => {
  try {
    const query = `
      SELECT 
        j.id, j.title, j.location, j.employment_type,
        j.description, j.responsibilities, j.requirements,
        j.form_url, j.created_at,
        c.name AS category_name
      FROM job_vacancies j
      LEFT JOIN job_categories c ON j.category_id = c.id
      WHERE j.status = 'published'
      ORDER BY j.created_at DESC
    `;
    const [jobs] = await db.query(query);
    return res.json({ success: true, count: jobs.length, data: jobs });
  } catch (error) {
    next(error);
  }
};

Prediksi pertanyaan evaluasi dari Penguji / Asesor / Pembimbing Industri beserta jawaban teknis yang siap dipertahankan:

Q1: Mengapa pada tabel lowongan pekerjaan Anda menggunakan constraint ON DELETE RESTRICT untuk category_id?
Jawaban Pembelaan Presenter: Kami menggunakan ON DELETE RESTRICT secara sengaja agar sebuah kategori jabatan tidak dapat dihapus apabila masih memiliki data lowongan yang terhubung. Ini melindungi konsistensi data riil sistem rekrutmen dan menghindari terjadinya 'orphan records' di database.
Q2: Apa keuntungan menerapkan tabel singleton pada company_profile dibandingkan file konfigurasi JSON biasa?
Jawaban Pembelaan Presenter: Dengan menyimpan profil korporat pada tabel database singleton, administrator HRD dapat memperbarui visi, misi, deskripsi, dan logo perusahaan secara real-time melalui form CMS dashboard tanpa perlu redeploy aplikasi atau mengubah file konfigurasi di server.
