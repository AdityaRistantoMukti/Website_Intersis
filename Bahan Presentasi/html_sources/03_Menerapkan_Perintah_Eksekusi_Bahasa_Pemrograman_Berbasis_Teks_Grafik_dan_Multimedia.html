3.2. Strategi Debugging, HTTP Logging, dan Exception Handling

Kaitkan ke Codebase: backend/src/server.js & backend/src/middlewares/errorHandler.js

Debugging dilakukan secara terpusat untuk memastikan tidak ada kesalahan internal yang membocorkan kredensial sistem ke publik:

  • HTTP Traffic Monitoring: Menggunakan morgan('dev') untuk mencatat method, URL rute, kode status response, dan response time milidetik pada konsol terminal backend.
  • Centralized Error Interceptor: Middleware Express yang menangani error penolakan promise database, duplikasi key, dan kegagalan token autentikasi.
backend/src/server.js 
// Global Error Handling Middleware untuk Debugging Terpusat
app.use((err, req, res, next) => {
  console.error('[SERVER EXCEPTION]', {
    timestamp: new Date().toISOString(),
    path: req.originalUrl,
    method: req.method,
    message: err.message,
    stack: process.env.NODE_ENV === 'development' ? err.stack : undefined
  });

  return res.status(err.status || 500).json({
    success: false,
    message: err.message || 'Terjadi kesalahan internal pada server.',
    error_code: err.code || 'INTERNAL_ERROR'
  });
});

3.3. Pengelolaan Upload Media & Automasi Executable PDF Generator

Kaitkan ke Codebase: backend/src/middlewares/upload.js & generate_handbook_pdf.js

Pengelolaan file grafis multimedia dan skrip executable mencakup dua komponen utama:

  1. Middleware Multer Storage: Mengelola stream file upload foto profil dan galeri industri. File diverifikasi ekstensinya, dinamai ulang menggunakan kombinasi timestamp acak, dan disimpan ke direktori publik /uploads.
  2. Headless Chrome Automation (Puppeteer): Skrip Node.js mandiri yang mengontrol browser Chrome secara programmatic untuk mem-print dokumen HTML teknis menjadi berkas PDF A4 beresolusi tinggi tanpa intervensi manual.
generate_handbook_pdf.js 
// Automasi Pembuatan Berkas PDF Menggunakan Puppeteer-Core
const puppeteer = require('./frontend/node_modules/puppeteer-core');
const browser = await puppeteer.launch({
  executablePath: 'C:\\Program Files\\Google\\Chrome\\Application\\chrome.exe',
  headless: 'new',
  args: ['--no-sandbox', '--disable-setuid-sandbox', '--disable-gpu']
});
const page = await browser.newPage();
await page.goto('file:///' + htmlPath.replace(/\\/g, '/'), { waitUntil: 'networkidle0' });
await page.pdf({
  path: outputPath,
  format: 'A4',
  margin: { top: '16mm', bottom: '16mm', left: '16mm', right: '16mm' },
  printBackground: true
});
await browser.close();

V. Matriks Tanya Jawab & Panduan Pembelaan Sidang (Q&A Defense)

Prediksi pertanyaan evaluasi dari Penguji / Asesor / Pembimbing Industri beserta jawaban teknis yang siap dipertahankan:

Q1: Mengapa Anda menggunakan 'puppeteer-core' dan mengarahkan executablePath ke Chrome lokal, bukan 'puppeteer' standar?
Jawaban Pembelaan Presenter: Penggunaan puppeteer-core menghindarkan pengunduhan binary Chromium tambahan sebesar 300MB ke dalam node_modules. Kami memanfaatkan executable Chrome resmi yang sudah terpasang di sistem operasi host, sehingga eksekusi lebih cepat, hemat bandwidth, dan hemat kapasitas penyimpanan.
Q2: Bagaimana Anda mencegah celah keamanan saat pengguna mengunggah file media ke server?
Jawaban Pembelaan Presenter: Kami menerapkan fileFilter pada Multer untuk memeriksa header MIME type (hanya mengizinkan image/jpeg, image/png, image/webp), membatasi ukuran maksimal 5MB, serta mengubah nama asli file menjadi hash timestamp acak untuk mencegah penimpaan file sistem atau eksekusi remote script (.php/.sh).
