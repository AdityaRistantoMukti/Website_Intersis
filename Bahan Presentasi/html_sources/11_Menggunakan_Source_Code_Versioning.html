I. Peta Outline & Struktur Pembahasan

Unit kompetensi Menggunakan Source Code Versioning ini disusun secara berkesinambungan mencakup seluruh sub-judul yang didefinisikan pada diagram alur kompetensi, diaplikasikan langsung pada arsitektur website yang telah dibangun:

  • Alur kerja branching: Menerapkan alur branching Git-Flow / Feature Branching (master/main produksi, fitur modular dan hotfix).
  • Merging: Mengintegrasikan perubahan kode, fast-forward merge, pengelolaan merge conflict, dan validasi pasca merger.
  • Commit: Menulis commit atomik dengan pesan berstandar Conventional Commits (feat, fix, docs, style, refactor).
  • Push/Pull: Menyinkronkan delta commit ke remote GitHub dan memicu pipeline CI/CD Continuous Deployment Vercel & Railway.
  • Cloning: Menduplikasi proyek ke lingkungan baru, konfigurasi dependensi, dan restorasi skema basis data dari fresh state.

11.2 & 11.3. Strategi Alur Kerja Branching & Resolusi Konflik (Merging)

Kaitkan ke Codebase: Git Branching Workflow

Siklus hidup isolasi fitur dan penggabungan kode sumber:

Alur Branching & Merging 
[master / production] -------------------------------------------------> [Deployment Vercel/Railway]
          ^                                               |
          |  (git merge --no-ff)                          | (git pull)
          |                                               v
[feature/products-module] -----> [Commit 1] -> [Commit 2] -+
Terminal Commands: Branching & Merging Cycle 
# Membuat branch fitur baru yang terisolasi
git checkout -b feat/products-module

# Mengembangkan kode dan melakukan commit atomik
git add .
git commit -m "feat(products): create responsive bento product showcase"

# Berpindah ke master dan menggabungkan perubahan
git checkout master
git merge feat/products-module

# Menghapus branch fitur lokal pasca merge sukses
git branch -d feat/products-module

V. Matriks Tanya Jawab & Panduan Pembelaan Sidang (Q&A Defense)

Prediksi pertanyaan evaluasi dari Penguji / Asesor / Pembimbing Industri beserta jawaban teknis yang siap dipertahankan:

Q1: Bagaimana strategi Anda dalam menyelesaikan Merge Conflict saat ada perubahan bertabrakan?
Jawaban Pembelaan Presenter: Ketika terjadi merge conflict, Git menandai baris yang bertabrakan dengan marker <<<<<<< HEAD, =======, dan >>>>>>>. Kami melakukan inspeksi manual bersama rekan tim untuk menganalisis baris logika mana yang harus dipertahankan, membersihkan marker konflik, menjalankan pengujian unit/sistem lokal untuk memastikan aplikasi tetap berjalan, lalu melakukan commit resolusi merge.
Q2: Mengapa penting menulis pesan commit dengan pola Conventional Commits?
Jawaban Pembelaan Presenter: Conventional Commits memformat pesan commit menjadi terstruktur mesin dan manusia (misal feat untuk fitur baru, fix untuk perbaikan bug). Hal ini memudahkan pelacakan changelog otomatis, pemahaman riwayat perubahan oleh tim, dan memfasilitasi penentuan kenaikan nomor versi Semantic Versioning secara otomatis.
