6.1 & 6.2. Validasi Tipe Data & Pola Percabangan Guard Clauses

Kaitkan ke Codebase: backend/src/middlewares/authMiddleware.js

Pola Guard Clause diterapkan untuk menyederhanakan alur percabangan dan menjamin keamanan rute sebelum data diproses lebih lanjut:

backend/src/middlewares/authMiddleware.js 
// Penerapan Guard Clauses: Mencegah Nested If Berlebihan
const verifyToken = (req, res, next) => {
  const authHeader = req.headers['authorization'];
  
  // Guard 1: Periksa keberadaan header
  if (!authHeader) {
    return res.status(401).json({ success: false, message: 'Akses ditolak: Token tidak ditemukan.' });
  }

  // Guard 2: Periksa format Bearer
  const token = authHeader.split(' ')[1];
  if (!token) {
    return res.status(401).json({ success: false, message: 'Format token tidak valid.' });
  }

  try {
    const decoded = jwt.verify(token, process.env.JWT_SECRET);
    req.user = decoded;
    next(); // Lolos validasi, lanjutkan ke controller
  } catch (err) {
    return res.status(403).json({ success: false, message: 'Token kadaluarsa atau tidak sah.' });
  }
};

// Filtering Multi-Parameter & Transformasi Array Deklaratif
const filteredJobs = useMemo(() => {
  return jobs.filter((job) => {
    const matchesSearch = job.title.toLowerCase().includes(searchTerm.toLowerCase()) ||
                          job.description.toLowerCase().includes(searchTerm.toLowerCase());
    const matchesCategory = selectedCategory === 'all' || job.category_id === Number(selectedCategory);
    return matchesSearch && matchesCategory;
  });
}, [jobs, searchTerm, selectedCategory]);

6.6. Operasi File I/O & Pembersihan Berkas Fisik di Server

Kaitkan ke Codebase: backend/src/controllers/admin/adminContentControllers.js

Sistem mengelola berkas media fisik di storage lokal backend menggunakan modul inti fs dan path:

backend/src/controllers/admin/adminContentControllers.js 
const fs = require('fs');
const path = require('path');

// File I/O: Menghapus File Gambar Fisik dari Disk Saat Record Dihapus
exports.deleteGalleryItem = async (req, res, next) => {
  try {
    const { id } = req.params;
    const [rows] = await db.query('SELECT image FROM gallery WHERE id = ?', [id]);
    
    if (rows.length > 0 && rows[0].image) {
      const filePath = path.join(__dirname, '../../../uploads', rows[0].image);
      // Validasi keberadaan file sebelum penghapusan
      if (fs.existsSync(filePath)) {
        fs.unlinkSync(filePath); // Eksekusi penghapusan file dari filesystem
      }
    }

    await db.query('DELETE FROM gallery WHERE id = ?', [id]);
    res.json({ success: true, message: 'Item galeri dan berkas fisik berhasil dihapus.' });
  } catch (err) {
    next(err);
  }
};

V. Matriks Tanya Jawab & Panduan Pembelaan Sidang (Q&A Defense)

Prediksi pertanyaan evaluasi dari Penguji / Asesor / Pembimbing Industri beserta jawaban teknis yang siap dipertahankan:

Q1: Apa perbedaan manipulasi array imperatif (for loop biasa) dengan fungsional (.map/.filter) dalam konteks React?
Jawaban Pembelaan Presenter: Metode fungsional seperti .map() dan .filter() bersifat declarative dan immutable (menghasilkan array baru tanpa mengubah data asal), yang sangat krusial dalam siklus hidup React untuk memicu re-render secara akurat berdasarkan perbandingan referensi (shallow comparison).
Q2: Mengapa Anda memeriksa fs.existsSync() sebelum menjalankan fs.unlinkSync()?
Jawaban Pembelaan Presenter: Jika kita memanggil fs.unlinkSync pada path file yang sudah tidak ada di disk (misalnya file terhapus manual oleh admin server), Node.js akan melempar ENOENT exception yang dapat menyebabkan kegagalan request. Validasi keberadaan file menjamin operasi penghapusan record database tetap sukses.
